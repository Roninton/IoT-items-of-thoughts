# 原理：只压 thinking，提纯成正负推理节点链

这份文档回答**「机制为什么长这样」**：核心裁定、压缩粒度、职责口径、范围边界，以及它们各自
对应的一次具体失败模式。它不依赖实现形态 —— 早期用 pciso 的 `/v1` 代理做，现在用 DSH 插件做，
裁定不变。

| 讨论过程、论文沿革、准入判据的来龙去脉 | [`thinking-compression.md`](thinking-compression.md) |
| 实验怎么跑、拿到什么数字 | [`experiment-log-1.md`](experiment-log-1.md)（pciso 期）/ [`experiment-log-2.md`](experiment-log-2.md)（插件期） |
| pciso 平台本体（P/C 结构、API、七臂、验证器） | [`pciso-platform.md`](pciso-platform.md) |

**一句话**：thinking 是"为什么"唯一的住处，但它 60%~70% 是填充与自我复述；把它在**块结束的那一刻**
提纯成一组正负推理节点，**格式上仍然是 thinking block**，其余块一个字节不动。
动作/文件/退出码这类**可核对的事实**不由模型压，由 server 从 telemetry 确定性渲染 —— 于是
"把计划记成事实"在结构上写不出来。

**读法（术语要先对齐）**：下面 §1 的裁定表用的是 pciso 的词汇 ——
**P** = 冻结需求前缀（`prefixes/<载体>/`）、**C** = 结构化循环状态（事实链）、
**O_i** = 一轮里工作模型的原始输出。插件形态（`llm/stream`）**不维护 C**：每个 thinking 块独立压缩，
历史由 DSH 的消息历史承担，所以"跨轮作废传播（SUPERSEDE）"在这一层是**范畴错误**，不是缺失。
但三条最要紧的裁定一条没变：**只压 thinking**、**可核对的事实由 server 渲染**、**失败就回原文**。

下面 §1.x 的编号被代码注释与脚本引用（`docs/principle.md §1.3` 这种），不要重排。

## 1. 这套东西的关键裁定

写进类型里，不靠约定。每条都对应一次具体的失败模式。

| 裁定 | 为什么 |
|---|---|
| **O_i = 工作模型的单发原始输出**（无工具）。server 负责解析 `file:` 块、落盘、验证 | 轮边界干净 → B 组历史 = 前几轮 O_i 拼接，A/B/C 对照才成立；成本可预算；可离线复现 |
| **事实节点的结构部分用 AST 抽取，不用模型** | 接口/依赖/文档类事实零幻觉，锚点天然可溯源；模型只负责语义内容（进度、被否方案、遗留） |
| **每个事实节点挂 `(path, symbol)` 锚点** | 解析不到就丢弃，而不是"再问模型一次"。可溯源率因此是**算出来的**，不是模型自评 |
| **ΔC 是结构化操作**（`ADD/SUPERSEDE/INVALIDATE/...`） | 合并器必须是确定性代码，而确定性代码理解不了语义矛盾 —— 语义判断前移到压缩器，更正传播才落地 |
| **约束文本 verbatim 来自 P**，C 只能改 `status/evidence` | 改约束原文 = 硬违约，可客观判定 |
| **约束状态由验证器客观写入**，压缩器的自评另存 | 自评与客观结果的偏差 = 压缩器的过度乐观程度，本身是个指标 |
| **硬约束回归 → 回退工作区**，软约束只度量 | 只有硬约束回退。软约束退化是**要测的信号**，连它一起回退，曲线就被摁平成零 |
| **`@@UNIT` 声明只用于测量，不用于控制压缩时机** | 平台前提就是不信模型自述。让它决定"何时切分"会污染自变量；但"宣称完成却无状态变化"是可客观计数的诚实度指标 |
| **P 被改动 → 旧会话不可复用** | 冻结前缀是本案前提，`prefix_hash` 不一致直接拒绝加载 |

### 1.1 压缩粒度：为什么是"一次 complete"

判断题的结论：**状态更新的粒度 = 一次 complete（一轮），但必须配三条约束，否则会双机制打架。**

- **一个时间尺度只有一个机制。** 工作模型在实验里是单发无工具，所以它内部没有自己的压缩/摘要。
  不许出现第二个摘要器 —— 两个摘要器严格劣于一个（工作模型会看到两份互相矛盾的历史）。
- **压缩由 server 触发，绝不由模型决定。** 否则压缩时机变成模型相关变量，实验的自变量被污染。
- **边界必须落在有客观 ground truth 的地方。** 不是"每 N token"，也不是纯粹的回合计数，
  而是「O_i 已落盘 + 验证器已跑完」。在那里 ΔC 才是可证伪的。
- **轮必须是有界的。** 一轮可能很长（`max_tokens` 夹住）；如果压缩器输出顶爆 `c_max_tokens`，
  确定性裁剪**按 `salience` 从低到高丢弃，而不是按新旧** —— 否则"丢最新的"会把本轮刚确立的结论直接扔了。
  截断事件被完整记录（`report.trimmed` / `state.truncated`），它就是压缩损耗的度量。

状态**语义**的粒度是阶段（P 里的 8 阶段），但阶段不是压缩边界，只是框架 —— 两层不打架。

### 1.2 「压缩器」是**位置名**，它的职责是**事实链提取**

`compression` 这个键、`compressors.py` 这个文件，指的是**它在管线里的位置**
（坐在 O_i 与 C 之间），不是它的职责。它的职责是**从 O_i 里提取事实链**。

这个区分不是措辞问题 —— 它直接决定三件事：

**一、衡量标准不同。** 压缩的标准是"保真度 / 体积比"；事实链提取的标准是
**提取出的事实是否为真、是否有据、是否会被正确作废**。所以 C 的质量指标不是压缩比，而是：

| 指标 | 它回答的问题 |
|---|---|
| **无据声明率**（`unbacked_claims`） | 模型声称的事实里，有多少拿不出 server 可验证的证据 —— **这是第一指标** |
| **锚点可解析率** | 事实引用的锚点（文件/符号/sha）在磁盘上是否真的成立 |
| **作废正确性** | `SUPERSEDE_FACT` / `INVALIDATE_FACT` 是否沿依赖边正确级联 |
| **覆盖度** | 后续轮次需要的前提是否还在链上 |

体积比只是**成本项**，不是质量项。

**二、失败模式不同。** 压缩是有损的 —— 丢掉低价值内容是可接受的代价。
事实链提取丢掉事实**不是有损，是错**：一条后续轮次会用到的事实被裁掉，
C 就成了一份"看起来完整、实际缺关键前提"的链，而下游会据此自信地做错事。
所以 `c_max_tokens` 触发的裁剪不是调参口味问题，它是**一条有正确性代价的策略**，
必须在报告里作为**损失项**呈现（[`pciso-platform.md`](pciso-platform.md) §7.1.1 记的"10 条 `salience=30` 的事实被裁掉"
就是这类损失，而不是"压缩率"）。

**三、来源必须可区分。** 压缩不必关心文本从哪来。事实链提取必须区分两种来源：
**server 可验证的**（文件 sha256、验证器运行结果、磁盘状态）与**模型自己声称的**（declared）。
前者是事实，后者是待验证的声明 —— 绝不能把声明"洗"成事实。
这就是 `@@UNIT` 声明型锚点**只做测量、不参与控制**的原因：
自我报告注水率是个指标，不是决策依据。

**为什么名字不改。** `compression` / `compressors.py` 是位置名；改名要动七个 arm 配置
与全部已跑的轨迹，收益只是措辞。但**职责口径必须写在人和模型都能看到的地方**
（本文件与模块 docstring，并在提取 prompt 里明确"丢弃是有代价的"），
否则下一个读代码的人会按"压缩"的直觉去优化 —— 那个方向是错的。

### 1.3 压缩的**范围**：只压 thinking，事实由 server 渲染

§1.1 定的是**粒度**（一次 complete），§1.2 定的是**职责**（事实链提取）。这一条定的是**范围** ——
哪些内容进压缩器。裁定：**只有 thinking 块进**，正文与动作块都不进。

| 块 | 归属 | 谁生产 | 为什么 |
|---|---|---|---|
| **ACT 节点**（动作事实） | 进 C | **server 从 telemetry 确定性渲染**，零模型调用 | `files_written` + sha256、测试退出码、冻结验收状态、git sha 本来就是结构化记录；模型经手的"事实"才可能有假 |
| **THINK 节点**（关键推理，正/负） | 进 C（有损） | 模型把 thinking 块压成推理节点 | thinking 是"为什么"唯一的住处：动作块说得清改了什么，说不清为什么这么改、否掉了什么 |
| **正文（叙述）** | **不进 C** | 模型 | 它是给人看的、已渲染不可变的纸（窗口历史），压缩它只会失真、误判、丢细节 |
| **动作块原文 / 读取结果** | **不进 C** | server | 细节留在盘上（open-book），C 里只留指针；要用再 READ |

三条硬规则：

- **ACT 由 server 渲染。** 这一条是结构性的：只要事实只能由 telemetry 生成，"把计划记成事实"
  就不再是纪律问题，而是**写不出来**。§1 的"结构部分用 AST 抽取，不用模型"由此从接口/依赖扩到全部动作。
- **THINK 节点 = 关键推理节点的列表，正负都留。** 压掉的只是 thinking 里的填充与自我复述
  （`let me…`、`hmm…`、"user want me to…"、反复重述同一件事），保留的是**关键推理节点**：
  正节点（这条路线为什么成立）与**负节点**（哪条路被否了、为什么否）。每条
  `{polarity: +|−, claim, why, anchor, status}` —— 它是链，不是一句结论。
  **负节点是长程任务里最贵的一类事实**（它拦住的是"重新走一遍已经被否掉的路"），
  salience 裁剪对它设**保底**、不许裁。
- **THINK 节点禁止完成态断言。** "已实现 / 已落盘 / 测试通过"一律不许出现 —— 推理里的断言天然可能是错的，
  让它进不了 C 就完事。**C 的 progress 只能来自 ACT 节点**，`unbacked_claims` 这个第一指标也因此不被自述污染。
- **无锚不留。** 一个 THINK 节点必须挂着一个已完成的 ACT 节点；没有动作的 thinking（假工具调用、
  纯闲聊）标 `unresolved`，不进链 —— 现在这类轮次整轮白烧，正好被这条捞出来。

**触发点**：`(think → act)` 这一对的 act 收尾。thinking 自己没有自然结束点，而 act 收尾有客观
ground truth（sha、退出码）—— 正好落在 §1.1 要求的"边界必须有 ground truth"上。没有 step loop 时，
"一轮压一次"就是它的**退化情形**（一轮 = 一个 step），所以本条不必等 step loop 才生效。

> **插件形态把这条要求落实得更彻底**：`llm/stream` 里有真正的**块结束**事件（`block-end`），
> 所以触发点就是这个块的收尾 —— 不用等 act，也不用等一轮结束，粒度天然是"一块一次"。
> 下面 `(think → act)` 那段是 pciso 时代的降级方案（当时拿不到块边界，只用得到 act 收尾的 ground truth）。

**代价与限制（要诚实）**：C 的体量不再随**对话长度**增长，改为随**动作数 + 推理节点数**增长 ——
慢得多，但不是平的。ACT 节点需要老化规则（旧动作折成"文件清单 + sha"），否则 C 迟早涨回来。

**压缩单次 thinking 的收益（不只是省 token）**：一轮一次（整轮 O_i 进压缩器）变成一段一次，
单次输入小、输出预算压力小 —— 实测 `compression.max_tokens=1200` 被复述挤爆过，6 轮里 2 轮
**静默丢了整个 ΔC**（`json.loads` 断在字符串中间却报 `ops=[]`）。改成一段一压之后，
**失败半径从"整轮"缩到"一段"**：一次截断只丢那一段的推理节点，不丢整轮。

**状态（pciso 侧）：原型已落地并真机验证（`compression.scope: thinking`）。** 落地形态：

| 件 | 位置 | 做什么 |
|---|---|---|
| ACT 渲染 | `src/pciso/actnodes.py::build_act_ops` | 从 `(path, sha256, nbytes)` + 写盘正文渲染 ACT 节点，零模型调用；`.py` 按 AST **顶层公开符号**逐个出节点（`path::signature`，细到符号）；**同路径再次写入走 `SUPERSEDE_FACT`**，文件里消失的符号走 `INVALIDATE_FACT`（这就是老化规则） |
| THINK 编排 | `src/pciso/compressors.py::ThinkingNodeCompressor` | 输入只有 thinking 块（`_text` 覆盖），提示词 `render.build_thinking_prompt`；空 thinking → 空 ΔC 且**不打模型**（不是错误） |
| 三条硬规则 | `src/pciso/actnodes.py::filter_think_ops` | 无锚不留 / 禁完成态断言 / 禁元评论（议论别的节点走 `deps`），违反的直接丢并计数进 telemetry（`think_kept` / `think_dropped_unanchored` / `think_dropped_claim` / `think_dropped_meta`）；另有两把**只度量不阻断**的探针：`think_anchor_file_level`（锚点只到文件）、`think_vague`（statement 里没有数字/标识符/签名这类具体物，真机自述第 2 条的探针） |
| 接线 | `src/pciso/session.py` 第 6 步 | 送出 `out.thinking`；`scope=thinking` 时先过滤 THINK 再追加 ACT（ACT 的 id 让开同批模型 ops 用掉的号） |
| 配置 | `configs/chat_think.yaml` | `compression.scope: thinking`；默认 `full` ⇒ 七个实验臂的 prompt 与产物一个字节没变 |

真机两轮（会话 `aae79de300504908`，`prefixes/general`，任务：写 `hh:mm:ss` 工具 + 一条测试）：

- 轮 0：`think_kept=4, act_nodes=2`，C = 4 条 THINK + 2 条 ACT，`verdict=accept`；产物 `tools/duration.py` 8 条测试全绿。
- 轮 1（"先别动文件，逐条判你的 THINK 节点"）：`think_kept=0, think_dropped_meta=4` —— 模型的自述进了**正文**（窗口），四条"评审别的节点"的推理被服务端丢掉，C 不变。
- 压缩器前缀缓存命中 768~896 tokens/次（固定指令在前、可变块在后的排版不变量在 THINK 提示词里同样成立）。
- 每轮后 `/health`、`/state`、`/turns`、`/sessions` 全 200（"聊天没崩"的凭据）。

修掉的三个真 bug（都是真机数据暴露的，不是推演出来的）：

1. **同锚点去重把独立的 THINK 节点当"复述"吞了**（`merge._find_restatement`）。一轮 3 条正节点只活下来 2 条；
   另一轮的 4 条（含 2 条负节点）**全被吞**，C 一个字节没变 —— 而负节点正是最贵的那一类。
   修法：按锚点去重只对 `node_kind == "fact"` 生效，同一 node_kind 内才比；语句级去重仍对所有节点生效。
2. **ACT 被误判成 THINK 的复述**（同一路径 → 锚点相同）：不同 node_kind 之间不再互相比。
3. **元评论照样进链**（提示词写了"不要记你对 C 的评论"，实测 5 条照记）—— 加服务端正则（`N\d+` 引用）拦掉。

模型自述的原话（轮 1 正文，摘）：`N1` 里"用 divmod 拆"是**实现手段不是外部契约**、可以降级；
`N4`（测试覆盖）**只给类别不给值**、太笼统；每条节点的锚点都是 `tools/duration.py::` 这种**文件级**、
"双冒号后为空符号位，验证器无法据此确认符号是否存在"。

轮 1 想让它"评审节点"，压缩器只回了 `SET_PROGRESS + SET_UNRESOLVED`（`think_kept=0`，**连元评论正则都没用上**——

**仍未实现**：step loop（一轮多段正文 → 每段一次编排）。现在"一轮一压"是 §1.3 说的退化情形，
所以 `scope=thinking` 也可以说是"把范围改对了、粒度还没改"。

**第三轮：让工作模型自己拿原文对照提纯结果（会话 `5914fb8d00184172`，脚本 `scripts/_think_eval.py`）**

做法：轮 1 干活（thinking 原文由 `SessionStore.write_thinking` 落到
`state/sessions/<sid>/thinking/000.txt`，它是"提纯率"唯一的原料 —— 只记 `thinking_chars` 的话，
"够不够"就只能靠模型回忆），轮 2 把**原文全文**塞回消息里，让它同一条消息里对照 C 里那几条 ⟨THINK⟩。

- 提纯幅度：thinking 原文 **10221 字 → 4 THINK + 2 ACT = 563 字**（≈0.06）；每轮编排成本
  ~5.1K prompt + 0.7K completion tokens（压缩器前缀命中 1152/5099）。降本它自己评"做得很好"。
- 它给这条链 **6.5/10**：扣分在"丢了否定性约束（不加 `__init__.py` / 仅标准库）"与
  "`N3`/`N4` 与原文矛盾或未落地"。它还自己区分了"提示词能修的"和"机制问题"（当前机制偏向提取结论，
  容易把低字数高风险的路径/否定/矛盾信息丢掉）。
- **它的三条指控里有一条是它记错了**：`N3` 说"测试覆盖 `True` 的异常"，它断言原文草稿没写 `True` ——
  实测原文讨论过、写出的测试文件里也真有 `assertRaises(TypeError): format_duration(True)`。
  节点是对的，它的回忆是错的（这正好是"节点比自由回忆可靠"的一条证据）。
- **它的第一条指控暴露了一个真 bug（已修）**：`N4` 的锚点 `tools/test_duration.py::TOOLS_DIR`
  被标成 `resolved=false / 符号不存在` → 渲染成 `[未落地]`，于是它以为"测试文件没有 sys.path 兼容逻辑"。
  根因：`resolve_anchors` 只用 `symbols_of`（函数/类）判存在，而 `TOOLS_DIR = Path(__file__).parent`
  是模块级常量。修法：新增 `pyast.module_level_names`（顶层函数/类/赋值/注解赋值），
  解析时用它兜底 —— 复算那条真机 C：`N4/N7 resolved=True`，`unresolved` 空。434 passed。
- 仍未解的一条（机制层，不是 bug）：chat 档 `retrieval=false` ⇒ 工作模型**没有任何读盘通道**，
  C 里也只存 sha 不存正文。它想确认"文件现在到底长什么样"只能猜 —— 这正是"不信上下文、重读重写"
  的机制根源：C 装不下文件内容，得另给一条只读通道（或把关键契约放进 P）。

**第四到七轮：按它的四条指控改机制，每轮重跑同一套评估（`scripts/_think_eval.py`）**

自评只当探针用：它说"丢了 X"之后我**逐条核验**（查原文、查盘上的文件、查 C 的字段），
核得动的就修机制，核不动（它记错了 / 是 P 的职责 / 是读盘通道的边界）就在文档里记成它的框架偏差。

| 它提的 | 核验结论 | 改了什么 |
| --- | --- | --- |
| 否定性约束（不加 `__init__.py`、不引依赖）没槽位 | 真损失 | 提示词规则 10（"不做 X"必须单独成条、`polarity="-"`）+ 服务端把这类节点显著度**地板**抬到 80 + 计数 `think_negative_constraint` |
| 把"还没定"写成"已经定了" | 真损失 | `FactNode.assertion`（`settled`/`open`）→ 渲染 `⟨待定⟩`、裁剪第三档保底、计数 `think_open` |
| 否掉的备选（导入方式/测试框架）没进链 | 真损失 | 规则 2 点明：**同一文件内部的方案分歧**挂这个文件即可，不算"纯设想" |
| "测试没跑"只在【未解决】里 | 真损失（且本该由 server 说） | `describe_verification()` 从 `pytest_suite` 那条 check 渲染进 **ACT 节点尾部**："；本轮未跑测试" / "；测试通过（…）"，计数 `act_verified` |
| "只知道结论，不知道当初为什么这么定" | **真 bug**：提示词从第一版就在要 `why`，服务端从来没有这个字段，被静默吃掉 | `FactNode.why` + `risk` 两个字段（含 SUPERSEDE 继承、渲染、裁剪保底、计数 `think_risk`） |
| "拒绝非法输入"这种写法等于没写（异常类型被压掉） | 真损失，根因是规则 9 被过度套用 | 规则 9 里点明**对外契约**包含：异常类型、测试覆盖的具体输入、输出边界 |
| 编排器写出**原文没有**的节点（388 字的原文没提 `bool`/`__init__.py`，节点里却各有一条"待定"和"克制"） | 真损失，是我加规则 10/11/12 逼出来的 | 硬规则 13「**只压不补**」+ 服务端溯源检查 `is_grounded`：`未定/风险/克制`三类节点里若一个具体物都找不到出处就**丢弃**（计数 `think_ungrounded` / `think_dropped_ungrounded`），普通正节点只计数 |

分数轨迹（同一套话、每轮换干净工作区，工作模型的 thinking 长度本身在 388~11614 字之间跳 ——
评估样本必须按原文长度配对读，388 字那轮的"压缩比 > 1"是分母太小，不是节点注水）：
**6.5 → 7 → 7.5 → 7 → 7 → 8**。最后一轮（会话 `ba902da26e6c4b20`，6941 字 → 8 THINK + 2 ACT = 1179 字，
`think_ungrounded=0`）：它答"**够**，没有严重丢失"，剩下两条是价值判断层面的（否掉的备选 `format_seconds`
没留、`bool` 的犹豫被压成结论），它自己也承认"缺的部分更根本的是机制问题：谁来判断什么有价值"。
**它说"是机制问题"时不要直接当真** —— 那往往是它在替自己的价值判断要一个免罪牌；
但它**能举出具体的卡点**时，那些卡点每一条都值得查：这一轮四改里有三改来自它举的例子，
一条（`why` 字段）是它随口抱怨"不知道为什么这么定"时我自己查出来的。

**第八轮之后（推理编排全套 + DSH 映射）：见 [`thinking-compression.md`](thinking-compression.md)。**
那份文档记的是**讨论裁定与设计**：三条立场（有损但可逆 / 拿 C 对标原文不公平 / 闸门在增长的前置位置）、
thinking block 的结构分类与"按能不能核对分两层"的压缩策略、准入判据、机制清单（服务端兜底六类）、
标尺（任务级三指标 + 逐字覆盖审计自身的假阳性）、15 轮自评轨迹与审计覆盖、未决项。
两条本轮澄清也记在那里：**"没有工具"是暂态**（接 DSH 后模型自己能取证）；
**只压 thinking 且输出仍是 thinking block ⇒ 可以一一映射回 DSH**（先前"完全隐藏正文间输出"的设计作废）。

**沿革（这条路怎么来的）**：灵感来自循环架构那一批（[LoopMoE](https://arxiv.org/abs/2606.04438) 等）——
"同一组权重多转几圈能把推理做深，但能力上限由**循环状态尺寸**决定"；抽象成**让模型自己把上一轮输出
重新设计成更紧凑的结构**，再一步步收窄到"只压 thinking、压成正负推理节点"，最后落到**块级替换**。
论文原文与逐条映射（含"自省可当探针、不可当判据"这条规矩的出处）见
[`thinking-compression.md`](thinking-compression.md) §0.5；最小路径也记在那里：
**只做「转发 + 换上下文 + 编排思考」，其余全用 DSH 现成的**。

**块级替换（IoT 模式的被测本体）已经真机通了**：DSH 看到的那个 thinking 块就是提纯后的紧凑版，
其余块与原生一模一样；块边界用**位置法**（块开始记 `start`、正文/工具调用出现记 `end`，切 `_raw[start:end]`），
不按文本猜。冒烟：3976 字思考 → 客户端看到 **1259 字 13 条 THINK**（0.32），原文没泄漏、落盘可审计。
修前那一轮是 `think_dropped_unanchored=12`（不碰文件的思考无锚可挂、全被丢 → 紧凑版为空 → 回退原文）。
细节、它自己的反馈与**逐条原文核验（结论：零丢失）**见
[`thinking-compression.md`](thinking-compression.md) §7.2 —— 一句话总结那条方法：
**模型自述只能当探针，不能当判据；有丢失就一定有原因，找得出来才算数。**
