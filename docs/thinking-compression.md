# 推理压缩（thinking 编排）：设计、裁定与实测记录

这份文档记的是**讨论和设计**本身 —— 为什么这么压、什么算损失、怎么量、哪些还没做。
原理与裁定成文在 [`principle.md`](principle.md) §1.3（机制在代码里的位置与逐轮实测）；这里只把散在
多轮对话里的裁定收拢，免得下次接手时得重新推一遍。实验数字在
[`experiment-log-1.md`](experiment-log-1.md) / [`experiment-log-2.md`](experiment-log-2.md)。

---

## 0. 一句话

**只压 thinking block，压成"关键推理节点链"（正/负节点），格式上仍然是一个 thinking block。**
初心（用户原话）：**"不让思维链的有价值信息被淹没在 thinking 长文本下，提纯，且降本。"**

- 压的不是"正文之间的全部输出"（那条设计已作废，见 §2）；
- 事实（谁写了什么文件、跑没跑测试）**不由模型压缩，由 server 从 telemetry 渲染**，
  所以"把计划记成事实"在结构上写不出来；
- 一压一编的时机 = 一段 thinking 结束、下一个 block 开始之前（step loop 未做，现在退化成"一轮一压"）。

## 0.5 沿革：从 LoopMoE 到"节点化"，再到块级替换

这一节记的是**这条路是怎么来的**（原始灵感 → 抽象 → 一步步收窄 → 最小路径），
免得后来者以为我们一开始就在做"压缩 thinking"。

### 一、灵感：循环架构（LoopMoE 那一批）

| 论文 | 它说了什么 | 对我们的映射 |
| --- | --- | --- |
| [LoopMoE](https://arxiv.org/abs/2606.04438)（EMNLP 2026：loop + 稀疏路由，等参数等 FLOPs 下 3B 高 1 分、9B 高约 3 分；靠 **IterAdaLN**（圈数 + 隐状态调制）破权重共享对称性 + capacity balancing） | 同一组权重多转几圈，能把推理做深 | 模型分不清自己转到第几圈 —— 所以 C 的首段该由 server **确定性**给出"第 N 轮 / 阶段 / 上轮 verdict / 未决项数" |
| [CoT and Compressed Looped Transformers: A Memory-Budget Separation](https://arxiv.org/abs/2605.30757) | 压缩环的能力上限由**循环状态尺寸**决定；多转几圈只加算力、不长草稿纸。小状态环永远只是小空间推理器 | C（2000 token）就是那个"小状态"。**"用 C 替换全量历史"没错，错在想让它当唯一记忆** —— 装不下的留给 P / 磁盘 / 窗口历史；它"不信上下文、去重读重写"＝工作记忆不够在打补丁 |
| [Operational Proto-Introspection in Looped Language Models](https://arxiv.org/abs/2607.18553)（Ouro-2.6B：隐藏态能在出答案前读出"算得对不对"，AUROC 0.797 vs surface 0.731；**生成式控制全面无效**） | 自省**可作决策探针，不可作生成式控制** | 这正是"让它自述思考节点是否合理"的依据；也定了规矩：**自述不做判据** —— 实测它三次把原文里没有的东西算成"丢失"（§7.2） |
| [Looped Latent Attention](https://arxiv.org/abs/2607.15456) | 跨圈 KV 可以低秩，但**不能安全地塌成单一状态**；逐头 codec 打赢"只留最后一圈" | C 该逐条 keep / update / drop，而不是每轮重写一遍 |
| 循环架构的通性（Ouro 对照实验；Huginn 闭卷弱、开卷强，OBQA +11.0） | 循环擅长**操作**知识，不擅长**存储**知识 | C 是**操作台**，不是知识库 |

### 二、抽象（我们自己那一步）

从"循环 + 状态"里抽出来的一句话是：**别把历史喂给它，让它自己把上一轮的输出重新设计成更紧凑的结构。**
"模型自己重新设计输出"就是这一步的产物 —— 不是我们替它写摘要，是让它按一个**结构化 schema** 重写。

### 三、收窄（一步步收成这个形态）

1. 粒度：一次 `complete` 一次压缩，不按 token、不按新旧（[`principle.md`](principle.md) §1.1）；
2. 位置名改成"事实链提取"，第一指标是**无据声明率**（[`principle.md`](principle.md) §1.2）；
3. 范围从"正文之间的全部输出"收窄到**只有 thinking**，且输出仍是 thinking block ⇒ 能**一一映射回 DSH**（[`principle.md`](principle.md) §1.3）；
   机器可读的事实（改了哪个文件、测试退出码）改由 **server 确定性渲染**成 ACT 节点，零模型调用；
4. thinking → **节点化**：正 / 负推理节点 + 准入判据（§5）+ 服务端兜底六类；
5. 落地形态 = **块级替换（压缩后返回）**：一个 thinking 块一次编排，客户端看到的就是紧凑版（§7.2）。

### 四、最小路径（这一路真正找到的东西）

不需要自己实现 agent loop、不需要工具执行器、不需要动客户端：
**只做「转发 + 换上下文 + 编排思考」三件事**，工具循环 / 沙箱 / UI 全用 DSH 现成的。
`/v1` 兼容入口 + `src/pciso/proxyapi.py` 就是这个最小路径的全部（[`pciso-platform.md`](pciso-platform.md) §3.1.1）。

## 1. 三条立场（用户提，我认）

1. **压缩有损，但不是不可逆**：有些损失可以靠模型取证读回来（读文件、跑测试）。
   前提是得有一条只读回读通道 —— 当前 chat/think 档 `retrieval=false`，这条通道是断的（暂态）。
2. **拿 C 对标原文不公平**：长上下文本身的注意力也是有损的。我们做的不是"无损压缩"，
   而是**更好的上下文管理** —— 用一份逐条可核、可被服务端判定的状态，替掉"整段 thinking 全塞回去"。
3. **闸门在增长的前置位置**：相比"上下文到顶之后自动压缩"，我们是在每一段产生时就把它编排进 C，
   不让它先堆积再收拾。**零成本闸门**（正则先看这段有没有决定/否定/未定/代价标记，没有就不调压缩器）
   是这条立场的一个还没做的延伸。

## 2. 范围裁定：只压 thinking，且输出仍是 thinking block

用户裁定（原话）："或许我们应该压缩的只有 thinking block，对应压缩成思考节点，而不是压缩全部正文输出之间的内容。
……因为代码块执行，read edit 本身是事实块。全部压缩可能会导致失真、误判、丢失细节。"
随后又修正一条："而是通过压缩去掉了很多 let me.... uhmmm... user want me... let me reconsider... 而是保留关键推理节点
包括正负推理节点。这样只压缩单次 thinking，压缩轮的负担也更小。"（推理过程不是没了，是去掉了填充。）

本轮追加的澄清（**改变了 DSH 侧的接法**）：

> "现在我们只做 thinking block 的压缩，并且格式上仍然是 thinking block，这意味着我们可以
> 一一映射回 dsh，而不是完全隐藏正文间输出了。"

含义：
- 之前的设计是"DSH 只看得见正文，thinking / 工具调用 / 工具结果全由 pciso 吞掉"→ **作废**。
- 现在是：一个 thinking block 进去 → 一条 thinking 节点链出来 → **可以 1:1 映射回 DSH 的 thinking 段**。
  于是 DSH 那边不必改造"只显示正文"的语义，压缩结果本身就能作为正常的 thinking block 被消费。
- 一处仍需小心：C 是**跨轮累积**的（旧节点 + 本轮节点），而 DSH 的一段 thinking 是**单段**的。
  映射时给 DSH 的应当是**这一段新产生的节点**（ΔC 里的 think ops），C 整体仍只喂给工作模型自己。

同样地，**"没有工具"是暂态**：现在 chat/think 档工作模型没有读盘通道，所以"它想确认文件长什么样只能猜"；
接入 DSH 之后模型自己就能取证，§1 的第 1 条立场才真正成立。这一步的验证没做，别当已经解决了。

## 3. 一个 thinking block 里有什么（结构分类）

用户提的六类：**现状分析 / 过往方案现象 / 多方案并举 / 权衡 / 应该怎么做 / 预演**。
我补的观察（写下来是为了别照这份清单写分类器）：

- 这六类**不是流水线，是交错的**：决定 → 预演 → 发现漏洞 → 退回权衡，一轮里能来回好几次。
  任何"先分类再按类压缩"的实现都会在交错处出错。
- 少列了四类，其中两类体积最大：**读题复述块**（把用户要求又写一遍）、
  **元块**（对平台/格式的自我提醒："不要写 bash 块""只写跑过的 @@UNIT"）、
  **未定项**（"暂时不确定，先这样"）、**自我复核**（负节点常常藏在这里 —— "等等，这样会不会……算了"）。
- **权衡 vs 应该怎么做**常常在同一句里，硬切会把结论和理由分开。

**可用的切法不是按语义类别，而是按"能不能核对"分两层**：

| 层 | 内容 | 谁来定 | 为什么 |
| --- | --- | --- | --- |
| 可核对 | 写了哪个文件、什么符号、跑没跑测试、import 了谁 | **server**（从落盘结果 + telemetry 确定性渲染） | 模型自述在这层没有裁量权，幽灵事实在结构上写不出来 |
| 不可核对 | 权衡、否掉的路线、未定项、搁置的风险 | 模型提，**server 按规则验/补/丢** | 只有模型知道它想过什么；但"有没有结论""具体物在不在原文里"server 能查 |

## 4. 机制清单（谁做什么）

### 4.1 模型侧（提示词，`render.build_thinking_prompt`）

固定文字全在前、可变块（先验节点 / 落盘清单 / 原文）全在后 —— 这是前缀缓存的前提。
规则要点：丢填充与自我对话、保留正负节点；**禁完成态断言**（不许说"已实现/已修复/测试通过"）；
**无锚不留**；statement 要自足（文件 + 符号 + 参数 + 常量 + 输出格式）；
**只压不补**（具体物必须在原文出现，少输出甚至空 ops 是合格答案）；"不做 X" 单独成条；
没定的事不许写成定了的；已知风险用 `risk` 槽位；不确定的符号名一个都别写（只给 `anchor.path`）。

### 4.2 服务端侧（`src/pciso/actnodes.py`，零模型调用）

- `build_act_ops(*, prior_state, written, reserved_ids=())`：每轮真写出去的文件渲染成 `⟨ACT⟩` 节点
  （`写入 <path>（<nbytes>B，sha256 <12位>）`，salience 70），同路径旧 ACT 用 SUPERSEDE 顶掉；
  `_dedup_written` 保证同一路径一轮写两遍只留最后一次。
- `describe_verification(pytest_passed, detail) -> (小句, 状态)`：从 `pytest_suite` 那条 check 渲染
  "；本轮未跑测试" / "；测试通过（…）" 接到 ACT 尾部，`act_verified` 计数。
- `think_anchor_paths(prior_state, written)`：THINK 允许挂的路径 = 本轮写过的 ∪ 历史上 ACT 过的。
- `filter_think_ops(ops, *, allowed_paths, source='', constraint_texts=())`：硬规则闸门 ——
  无锚丢、完成态断言丢、元评论（`_META_REF_RE` 命中 `N\d+`）丢、`未定/风险/克制` 三类
  在原文里找不到具体物就丢（`is_grounded` / `is_uncertain_about`）；
  负节点**不再被降级成 `open`**（一条否决本身就是决定）；纯否定句强制 `polarity='-'`；
  复述 P 的负节点丢掉（`is_p_restatement`，用户给的准入判据见 §5）。
- `build_alternative_ops` / `build_dropped_import_ops` / `build_rejected_route_ops` /
  `build_shelved_risk_ops` / `reclassify_answered_questions`：五类"模型没记就服务端补"的负节点/风险节点。
- `with_act_nodes(delta, *, prior_state, written, sources=None, verify='', verify_state='', thinking='')`
  → `(merged_delta, stats)`：ops 顺序 = 模型 ops + act + 备选 + 被砍依赖 + 被否路线 + 搁置风险 + 已答悬案。

### 4.3 数据与渲染

- 字段（`models.FactNode`）：`node_kind`（fact/act/think）、`polarity`（+/-）、
  `assertion`（settled/open）、`why`、`risk`、`salience`；`Anchor.symbol_missing`（文件在、符号名不在）。
- 渲染（`render.render_state_block`）：`⟨ACT⟩` / `⟨THINK +⟩` / `⟨THINK -⟩` / `⟨待定⟩` /
  `｜依据：{why}` / `｜风险：{risk}`；`[未落地]`（文件不在）与 `[符号未见]`（文件在、名字不在）分开报。
- `_verification_line(state)`：【当前进度】后一行汇总最近一轮 ACT 的验证状态
  （"未跑测试（只有静态检查，没有任何运行结论）—— N7、N8"），零模型调用、不占 C 的存储、不会过期。
- `CompressionConfig.scope`（full/thinking，严格校验只认这两个值）+ `configs/chat_think.yaml`。
- thinking 原文落盘：`state/sessions/<sid>/thinking/{轮:03d}.txt`（`store.write_thinking`），
  它是"提纯率"唯一的原料 —— 只记 `thinking_chars` 时，"够不够"就只能靠模型回忆，而回忆不是证据。

## 5. 准入判据：什么值得进 C

用户给的判据（原话）：
**"重要 = 下一轮会因为它走错 / 重走贵路，而且从 P、盘上的文件、C 里其它节点都推不出来。"**

两条推论：
- **"有否定就记"该拦**：否定的内容如果只是把 P 里现成的约束复述一遍（"不修改冻结测试"），
  推得出来的信息不占 C 的预算 → `is_p_restatement`（共享具体物 ≥0.6）直接丢，只对负节点判。
- 代价不对称：**漏记一条会重走贵路的否决，比 C 里多一条噪声贵得多**；
  所以服务端兜底宁可多补一条带 `why` 的，也不要漏（用户对两条具体案例 —— "不加 `__main__`"、
  "try/except 被否" —— 的裁定是"不重要、有损压缩开销可接受"，但"有否定就记"这句本身要拦）。

## 6. 怎么量：标尺

自评只能当**探针**，不能当依据 —— 实测它两次编造损失：
①声称 `N3` 的 `True` 用例无出处（原文讨论过、落盘的测试文件里真有 `assertRaises(TypeError): format_duration(True)`）；
②声称丢了候选 `3599/86400`（原文通篇只有 `359999 -> 99:59:59` 和 `360000 -> 100:00:00`，落盘与之完全一致）。
所以真正的标尺是任务级的三项（前两项已有脚本，第三项在 telemetry）：

| 指标 | 出处 | 现状 |
| --- | --- | --- |
| 文件重写率（同一文件被反复重写占比） | `scripts/_trust_check.py` | 笔刷载体修前 42%（11/26）→ 修后 0%（0/8） |
| revert 次数 / 硬约束新违反 | `rounds.jsonl` 的 `judgement` | 同一批 6 轮：修前 2 → 修后 0 |
| 无据声明率 `unbacked_claims` | telemetry | 逐步纳入 |

**逐字覆盖率降级为上限参考**（`scripts/_think_audit.py`）：它逐条列原文里的候选信息点
（未定信号 / 克制否掉 / `A 或 B` 二选一 / 被否的代码结构 / 自问自答的悬案），
再看 C 里各有没有落点，并打印 `[P 已覆盖]`。**这个脚本自己也是会错的**，用时要一起读它的假阳性：

- 它一开始把"平台/回复格式的自我提醒"（要不要写 `note`、正文要不要写 shell 命令）当成项目推理损失；
- `__route__` 候选没做落盘判定，把**已被采纳**的 try/except 记成"被否的路线"（eval15）；
- 自问即刻自答的疑问（"是否需要处理非常大的 int？Python 无问题"）按 `open` 找，找不到就报 MISS；
- 单 token 命中会误判（把 `from __future__ import annotations` 算成被 `from/import` 覆盖）。
以上四条已修（`_PLATFORM_RE`、`landed_fallback`、`_RESOLVED_INLINE_RE`、`_grounding_tokens` 双 token 判据）。

## 7. 评估协议与实测

**协议**（`scripts/_think_eval.py`，每轮换干净工作区）：
轮 1 = 任务（把非负整数秒格式化成 `hh:mm:ss`，3725 → `01:02:05`，只用标准库，写 `tools/duration.py`
+ `tools/test_duration.py`）；轮 2 = 把**thinking 原文全文**塞回消息，让它同一条消息里对照 C 的
⟨THINK⟩ 回答四件事（够不够 / 丢了什么 / 丢对了什么 / 提纯降本打几分）+ A（有没有"不做 X"的克制、进链没）
+ B（有没有摇摆、节点呈现成已定还是待定）。口径澄清写在提示里：P 与平台约束每轮都在上下文、
文件在盘上，都不算"节点该装而没装"。

**提纯幅度**（thinking 原文字数 → 节点字数）：10221→563（0.06）、8875→995（0.11）、
9860→1106（0.11）、10837→1293（0.12）、8196→1150（0.14）、7336→1787、8192→1335。
**自评分数轨迹**（15 轮，1–10 分）：**6.5 → 7 → 7.5 → 7 → 7 → 8 → 8 → 7.5 → 7 → 7.5 → 7 → 7 → 7.5 → 7 → 7**，
headline 一直是"够用/够"，落在 7–8 区间波动 —— 单样本的分数只能当趋势，掉分那几轮往往恰好暴露一条真缺项。

**审计覆盖**（`_think_audit.py --simulate`，越接近满分越好）：eval9 4/4、eval10 17/17、
eval12 8/10、eval13 3/3、eval14 6/6、eval15 3/3。
eval12 剩的 2 条是**真候选**：原文里"可以不加 bool 检查，只检查 int"这条决定没进 C
（落盘的 `test_duration.py` 只有 `1.5 -> TypeError`，确实没有 bool 用例）。
它属于服务端兜底四类之外的形态 —— 一般性的"不做什么"仍得靠模型自己记，这是已知边界。

**成本**（真机一轮）：工作模型 prompt 约 1.5K tokens（缓存命中一半上下）、
压缩器 prompt 5.1K~6.9K（其中可缓存前缀 1529 tokens，命中 1.1K~3.0K）、completion 0.7K~1.0K。
C 自身预算 `c_max_tokens=2000` 远没满 —— 现在是**段太短**而不是"装不下"。

### 7.1 「有引导」到底有没有用：三臂对照（`scripts/_guided_ab.py`）

问的是最要紧的一件事：**我们那套规则 + 落盘清单，是不是装饰？**
做法：拿 6 段真机 thinking 原文（各 7.3K~10.8K 字），同一模型、同参数、同输出预算（1800）、
**同一份最小输出 schema**，各压一次，用**同一个** `coverage()` 量与同一道 `filter_think_ops` 闸门：

| 臂 | 覆盖 | 完成态断言 | 负极性 | 待定 | why | prompt | 命中缓存 | 节点字数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **guided**（现行提示词） | **31/43 = 72%** | **0** | **9** | **2** | 37 | 41905 | **81%** | 3194 |
| facts_only（只给落盘清单，无规则） | 28/43 = 65% | 3 | 3 | 0 | 23 | 20863 | 62% | 2210 |
| plain（只给原文） | 18/43 = 42% | 3 | 3 | 1 | 15 | 20707 | 62% | 2506 |

结论：

- **有效，而且是三件事各买各的**：
  - **看得到什么（信息）**：把"本轮真实落盘的清单"给它，覆盖率 42% → 65%（这是覆盖率最大的一跳）；
  - **怎么判（规则）**：负极性 3 → 9、待定 0 → 2、`why` 23 → 37，**幻影完成态断言 3 → 0**；
  - 两者一起才是 72%。**只给信息不给规则**时它照样会写"已实现/测试通过"这种完成态断言。
- **成本几乎是白送的**：guided 的 prompt 字数差不多是另外两臂的 2 倍，但那 2 倍几乎全是
  **稳定前缀**（固定文字在前、可变内容在后），实测命中缓存 **81%**。
  算**未命中 token**：guided 7985 / facts_only 7935 / plain 7907 —— 三臂基本相同（差 1%）。
  真正的差别只在 completion（5672 vs 4311/4226，+33%）和节点字数（C 的占用，+45%）。
- **逐样本看不是一边倒**：guided 在 6 个样本里 4 胜 1 平 1 负
  （`5f24337359ac4c39` 上 5/10 输给 facts_only 的 7/10）。所以别把"引导"当万能药，
  它买的是**口径**（负/待定/不许写完成态），不是每一条都记得更多。
- 一条留给标尺的自觉：guided 的节点更长，而 `coverage()` 是按"共享具体物"判命中的，
  更长的 statement 天然更容易命中。按"每个命中点的节点字数"看，facts_only（79 字/点）
  反而比 guided（103 字/点）省。**覆盖率不是越高越好，要看每单位 C 预算买到多少。**

复现：`python scripts/_guided_ab.py --limit 6`（结果落 `out/guided-ab/<时间戳>/report.md`）。

### 7.2 块级替换真机：压缩后返回（IoT 模式）

到这里机制才算真的在"客户端看得见的地方"生效：**一个 thinking 块一次编排，压缩后返回** ——
DSH 看到的那个块就是紧凑版，正文 / `tool_calls` / `usage` / `finish_reason` 与原生一模一样。

**块边界怎么找（位置法）**：`proxyapi.StreamScan` 在第一个 reasoning 字段出现时记
`start = len(_raw)`，`delta.content` 或 `delta.tool_calls` 出现时记 `end = len(_raw)`，
`_raw[start:end]` 即这一块原文；`(start, end)` 进 `events.jsonl` 的 `proxy_call.think_spans`。
不按文本判块（正文里逐字写 `{"reasoning_content": …}` 或 `<thinking>` 都不算思考），
一次响应支持多个块（工具往返之间各一段）—— 旧写法只认第一块，第二段会被静默吞掉。

**冒烟**（`scripts/_smoke_iot_stream.py`；纯推理题"跨时区解析时间戳的判断顺序"，明说不要动文件；
会话 `836e2644fe2646de`）：

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| 思考原文 | 3976 字 | 3976 字 |
| 客户端看到的块 | 回退原文（压缩比 1.00） | **1259 字 13 条 THINK（0.32）** |
| `think_dropped_unanchored` | 12（不碰文件的思考全被丢 → 块空） | 0（没锚只标记不丢；**编路径**才丢） |
| 原文落盘可审计 | 是 | 是（`state/sessions/<sid>/thinking/000.txt`） |
| C 记账 | — | 1 条 `kind=thinking_block`，N1..N13 全 `think` |

SSE 3315 事件、usage 785 / 3313、21.9s、`[DONE]` 正常收口。

**它自己的反馈，以及逐条核验**（第 2 轮问"知不知道自己的思维链被压缩了"）：
它说能看出来（依据是每条都套 `⟨THINK ±⟩ + 依据` 模板、13 条只覆盖一条线、`失败链（空）` 这类预置桶），
骨架也能续推（N1→N4 就是判定树、N9→N13 就是验收清单），然后提了三条"真丢"：

1. **"缺省策略全空 / '这是个坑'保住了，'我决定怎么办'大面积丢了"** → **不成立**。对着原文 108 行逐条核：
   四条裁决都在链上 —— IANA + `fold` 消歧、不许默认服务器时区/UTC、按量级判单位（不用固定位数）、
   双实现不一致即"歧义在输入"。它把"不许默认 X"读成了约束，没读成策略，这里面有**表述**的锅
   （论断式写法让裁决看起来像前提）。
2. **它点名的两条"我准备怎么办"**（缩写时区名怎么办、DST 的 02:30 该抛错还是挪到 03:30）→ **原文自己没定**：
   一处写"留一个歧义待确认"，一处写"看库是抛错、还是 fold=0/1、还是静默选一个"——那是**待观察**。
   原文没做的裁决，压缩器按规则 13（只压不补）不许替它补。
3. **"实例型数值丢了"**（2024-11-03T01:30 在 America/New_York 的两个 instant）→ **原文也没算过这两个 instant**。
   那些数是它想往下写测试时**需要**的，不是被压掉的。

结论：**零丢失**。它真正在说的是"这两处我当年该顺手定下来" = 自省，不是压缩损失。
这是它**第三次**拿原文里没有的东西当丢失（前两次：声称 `N3` 的 `True` 无出处、声称丢了候选 3599/86400）。

⇒ 方法上的铁律：**模型自述只能当探针，不能当判据**。每条"丢失"指控先去原文核
（`_think_audit.py` 就是那台秤）；核得到算我们的账，核不到就跟它算。
用户那句"**我不认为会平白无故丢失**"就是这个意思：有丢失就一定有原因，找得出来才算数。

它认下来**丢对的**：重复（N5/N6/N7 其实是同一个"静默错误"识别的三次重申被拆成三条并列）、
格式穷举与自我确认，估占原文 60%~70%。它另有一条观察值得留：13 条**全标 `(无锚)`**（纯思考轮没有工具动作，
标注准确），但这把"我查过的"和"我推的"区分抹平了 —— 低置信条目和推理性条目长得一样。

**缺省策略该在哪修**：不是提纯器（规则 13 不许补），而是**干活的模型**那侧 ——
识破一个坑就顺手给个兜底，别只写"这里有个坑"。

## 8. 未决

1. **step loop**：一轮多段正文 → 每段一次编排。现在是"一轮一压"的退化情形。
   上来之后同一套机制不用改，`compression.scope=thinking` 的调用点从"一轮一次"变成"一段一次"。
2. **零成本闸门**：段里没有任何"决定/否定/未定/代价"标记时直接跳过压缩器调用（正则判、零 token）。
3. **只读回读通道**：让模型能真读盘确认（现在是暂态缺失，接 DSH 后解决）。
4. **"被采纳决定的代价"槽位**：真机 eval15 的 `try/except 兜底导入`是**被采纳**的方案，
   它的代价（"会吞掉真正的 ImportError"）按定义不归负节点管，现在只能塞进 `risk`。
5. **一般性"不做什么"的兜底**：服务端只认四种形状（备选、被砍依赖、被否代码结构、搁置风险）+ 悬案回收。
6. **四臂真机对照（`iot` / `raw` / `drop` / `full`）**：机制已通（§7.2），"agent 能力不降甚至更强"还没量。
   同一任务、同一提示词、四个臂各跑一遍，比完成度 / 重写率 / 工具步数 / token。
7. **"边压边回"**：块还在流的时候就替换，客户端就不会"顿一下"。用户明说这是次要功能，先不做。
8. **"查过的 vs 推的"**：无锚节点现在一律 `(无锚)`，低置信条目（凭记忆说的库行为）和推理性条目长得一样，
   值得给一个置信度标记（能核对 / 不能核对）。
9. **缺省策略**：识破坑就顺手给兜底 —— 归**工作模型侧**的提示词（`CHAT_DIRECTIVE_BODY` / 阶段 directive），
   不是提纯器（规则 13 不许补）。
