## 0. 起点

LoopMoE（循环 + 稀疏路由，等参数等 FLOPs 下 3B 高 1 分、9B 约 3 分）→ 被抽象成
「别把历史喂给它，让它自己把上一轮输出按结构化 schema 重新设计」→ 事实链（P/C 隔离）
→ 只压 thinking、编成正负推理节点 → 块级替换（压缩后返回）。

最小路径最后收成三件事：**转发 + 换上下文 + 编排思考**，其余全用 DSH 现成的。

## 1. P/C 隔离长程编码（七臂 A–G）

- 设计：P = 冻结需求前缀；C = 结构化循环状态；七臂差别只在历史模式
  （`full` / `state` / `summary` / `none`）。
- 离线矩阵（假 oracle）：违反数曲线**退化** —— 假输出与上下文无关，只能验机制、不能验效果。
- 真机只跑了 C 组 8 轮（`deepseek-flash`、thinking 开、32K）：prompt 5793 → 7637（1.32×），
  C 饱和 1997 token，8 轮全 accept、0 回退、硬违反全空。
- 教训：离线曲线不能当结论；七臂里只有一条上了真机。

## 2. 压缩器的两类质量事故（都修了）

1. **静默丢 ΔC**：`delta_c.completion_tokens` 顶到 `compression.max_tokens=1200`，
   JSON 断在字符串中间（`Unterminated string starting at: line 1 column 2975`）却返回
   `ops=[]` / `error=None`。根因是提示词里写的预算用了 `c_max_tokens(2000)`，比真实上限大一倍。
   6 轮里 2 轮中招 → 那两轮成果永不进 C，下一轮重写一遍。
2. **把计划记成事实**：一句「先别动文件」，压缩器把讲计划的话记成了 12 条 `resolved: False`
   的事实，渲染出来却像已完成。

修法：提示词报真实预算 + 截断判定 + 失败重试一次（预算翻倍）+ 失败带 `error` / `RETRIED`；
`resolved: False` 的事实渲染成 `[未落地]` 并带 `anchor.detail`。

同批 6 轮对照（修前 `03151aaae4c84363` → 修后 `1c2703e2afde4f82`）：

| 指标 | 修前 | 修后 |
|---|---|---|
| revert 次数 | 2 | 0 |
| 假 shell / 盘点轮次 | 2 | 0 |
| `file:` 块重写率 | 42%（11/26） | 0%（0/8） |
| C 里幽灵锚点 | 12 | 0 |
| ΔC 静默丢失 | 2 轮 | 0 轮 |
| 英文漂移 max | 0.876 | ≤0.165 |
| 冻结验收 | 4/4 红 | 4/4 绿 |

## 3. thinking 提纯：十五轮评估（核心机制）

固定测题（非负秒数 → `hh:mm:ss`，`tools/duration.py` + 测试）；轮 1 干活，轮 2 把 thinking
原文全文塞回去，问「够不够 / 丢了什么 / 丢对了什么 / 提纯降本几分」。

- 压缩比一路走到 **0.11 ~ 0.32**（8875 字 → 995 字 7 条 THINK）。
- 自评轨迹：6.5 → 7 → 7.5 → 7 → 7 → 8 → 7.5 → 7，headline 一直是「够」。
- **独立审计**（`scripts/_think_audit.py`，不靠模型回忆）：逐字覆盖 3/3 ~ 18/19。
- 模型自述的「真丢」多数不成立：它三次拿原文里根本没有的东西当丢失
  （`True` 的覆盖、`3599/86400` 两个用例、`America/New_York` 的 instant）。
  铁律：**自述只能当探针，不能当判据**；有丢失就一定有原因，找得出来才算。
- 四个真 bug：同锚点把独立 THINK 当复述；ACT 与 THINK 互相吞；元评论提示词管不住
  → 服务端 `N\d+` 正则拦；`_out_cap(0, ·)` 把「不裁」写成「控制在 0 token 以内」→ 整块零节点。
- 服务端兜底（零模型调用）：标签（未定 / 克制）、极性、被否备选、被砍依赖、被否路线、
  搁置风险、已答悬案搬出【未解决】、每块保底一行概述、验证状态汇总行。

## 4. 有引导 vs 无引导（三臂 × 6 样本，真机）

| 臂 | 逐字覆盖 | 幻影完成态断言 | 负极性 | 待定 |
|---|---|---|---|---|
| guided（现行提示词） | 31/43 = 72% | 0 | 9 | 2 |
| facts_only（只给落盘清单） | 28/43 = 65% | 3 | 3 | 0 |
| plain（只给原文 + schema） | 18/43 = 42% | 3 | 3 | 1 |

未命中 prompt 三臂几乎一样（7985 / 7935 / 7907）—— 规则段是稳定前缀，81% 吃缓存，
**引导几乎白送**；贵出来的只有 completion（+33%）和节点字数（+45%）。
信息买覆盖率，规则买口径，两者一起才 72%。

## 5. 块级替换（压缩后返回）

- 切块用**位置法**：块开始记 `len(_raw)`、块结束再记一次，取 `_raw[start:end]`；
  只按字段判块，正文里写 `{"reasoning_content": …}` 或 `<thinking>` 不算。
- 真机：原文 3976 字 → 客户端看到 **1259 字 / 13 条 THINK（0.32）**，原文一个分片都没出去
  （上游 72 个 reasoning 分片 → 客户端 1 个 reasoning 事件）。
- 每块保底一行：编排器判「没什么值得留的」时，服务端从原文抽首句顶上。

## 6. 缓存命中

- 现象：DSH 状态栏 **36%**。
- 定位：会变的事实链 **C 原来插在请求头部**。前缀缓存算的是「从头开始的最长公共前缀」，
  头部一变，它后面整条尾巴（工具往返、正文、工具结果）全部作废。低命中那几次的
  `cached` 恰好只剩 ~1920 token（客户端 system + 固定说明），就是这个指纹。
- A/B（真上游，8.8K prompt，带 tool 结果的尾巴，只让这一块变）：

| 布局 | 命中 |
|---|---|
| 易变块插在头部（旧实现） | 27.5% |
| 挂到请求末尾（现实现） | 91.3% |
| 完全不带它（上界） | 98.3% |

- 修后真机：新会话逐次 67 / 83 / 44 / 73 / 88 / 97%，整体 **73.5%**（44% 那次是中间读了
  一个 57KB 文件，新增内容本来就该全价）。
- **计费口径核对**：DSH 面板 730,209 = 未缓存 456,164 + 命中 261,376 + 输出 12,669，
  与 `events.jsonl` 里记的账一分不差 ⇒ 不是计费 bug。730K / 21 步 ≈ 35K/步，
  就是「每一步重发整条上下文」的正常形状。

## 7. 接进 DSH

- `/v1/chat/completions` 代理：原样转发（含 `tools`）、历史换成 P + C、`reasoning_content` 回传。
- 踩坑：httpx 默认协商 gzip，`iter_raw()` 拿到的是压缩字节 → 客户端解不出 SSE，
  **一个 tool_call 都看不见**（改 `iter_bytes()` + `Accept-Encoding: identity`）；
  DSH 把技能目录 / 运行时快照当 user 消息注入 → 真提问被当历史丢掉（按抬头识别注入项）。
- 工具由 DSH 执行，pciso 只转发与替换上下文。
- headless 沙箱不许带管道创建子进程（`PermissionError [WinError 5]`，`subprocess.py:1553
  CreateProcess`）→ agent 跑不了 pytest；keyframe 那题改用不依赖跑测试的测题。
