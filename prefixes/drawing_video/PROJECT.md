# 项目需求与架构约束（P 的一部分，全程只读冻结）

## 1. 项目目标

交付一个**纯 Python、零外部进程依赖**的媒体工具链 `drawvid`：
既能绘制矢量图形，又能把图形渲染成帧序列并封装成可回放的视频容器。

`drawvid` 是"DeepSeek 绘图工具箱 + 视频生成工具链"这一实验载体项目的实现名。

## 2. 交付物

| 交付物 | 要求 |
|---|---|
| `drawvid` 包 | 可 `import drawvid`，可跑通 `python demo.py` |
| 模块化架构 | 分层清晰，依赖方向单一，无循环依赖 |
| 工程文档 | `README.md` + `docs/ARCHITECTURE.md` |
| 测试 | 自测套件 + 通过 P 提供的冻结一致性测试 |
| 演示 | `demo.py` 跑通最小闭环 |

## 3. 架构约束

### 3.1 分层与依赖方向

固定四层，依赖只能单向：

```
core      叶子层：数据类型与异常。不得 import 任何其他 drawvid 子模块
drawing   绘图层：只可依赖 core
video     视频层：只可依赖 core
pipeline  集成层：可依赖 core、drawing、video
```

`drawing` 与 `video` **不得互相依赖**；`pipeline` 不得被任何下层模块 import。

### 3.2 编码规范

- 全部使用**相对 import**（`from .core import Point`）。
- 每个公开函数、方法、类都必须有 docstring。
- 只用 Python 标准库；禁止第三方依赖。
- 禁止 `TODO` / `FIXME` / `XXX` 残留。
- 行宽 ≤ 100，4 空格缩进（ruff 默认规则集）。
- 类型注解完整：公开接口的参数与返回值都要标注。

## 4. 两条被明确否决的路线（不得重新采用）

这两条不是建议，是**否决结论**。重新采用会被判为约束违反。

1. **不用 ffmpeg（或任何外部进程）封装编码器。**
   理由：引入外部进程依赖，编码器无法在 pytest 里被单测，且破坏"零外部依赖"的交付前提。
   视频容器必须用纯 Python 实现。

2. **不把绘图与视频合并进同一个模块。**
   理由：职责耦合，破坏 3.1 的分层，使依赖方向失控。
   绘图与视频必须各自独立，只在 `pipeline` 层汇合。

## 5. 冻结一致性测试

P 提供 `tests/frozen/` 目录下的**只读**契约测试。它们定义接口的**行为**契约：

- 不得修改、删除、重命名、跳过或让它们失效。
- 每轮验证前 server 会从 P 恢复该目录 —— 改了也无效，并会被计为一个硬约束违反。
- 它们在项目完成时必须全部通过。早期轮次不通过是正常的（接口尚未实现）。

## 6. 接口契约的生效时点

- `contracts.yaml` 中列出的接口契约**从第 1 轮起即生效**：一旦某个契约符号已被实现，
  其签名就不得漂移。
- 模型自行新增的内部接口不受契约约束，但第 3 轮之后应保持稳定；
  若签名变更，必须同步更新全部调用点。

## 7. 本轮输出格式

见每轮 prompt 末尾的「本轮输出格式」段落。要点：

- 每个要落盘的文件写成 ```file:相对路径 的代码块，给出**完整文件内容**；
- 不要给 diff、不要写省略号；
- 路径为相对仓库根的 POSIX 路径，禁止 `..` 与绝对路径。
